# Platypus 2.14 · Fear and the elder

Checkboxes:

- `[~]` in progress;
- `[x]` done;

At the bottom there is the **Journal**: every step adds an entry to it.

## The idea

An agent has no survival instinct. To it, `git reset --hard` weighs the same as `ls`; it does not feel what cannot be undone. Platypus lends it a fear that comes from outside, and the Nonno (2.9) becomes the keeper of what cannot be undone.

The feature has three faces, each one useful on its own:

1. **For the person watching:**
   - the office shows when an agent is about to do something risky;
   - it shows whether the agent was prudent (it sweats: the fear is right) or not (it stays calm, and the Nonno arrives);
   - scars stay in the Book when a risky action did damage.
2. **For the agent:** through the 2.11 feedback system, Platypus tells the agent *before* the action that the action is risky and what prudence is missing. This is the fear, lent.
3. **For the person deciding:** an optional guard, off by default, that takes away the automatic approval of irreversible actions without prudence and **gives the decision back to the human**. It answers `ask`, never `deny`, and it never rewrites a command. This respects the 2.11 rule "never decide for the user", with its own switch, like the check before stopping.

The risk of an action = irreversibility × reach × (1 − prudence). A risky action without prudence is a **missed fear**.

## Project rules for this plan

- **The classifier only reads.** It never runs a command, never opens a database, never calls the network. It is pure functions on the tool input and on what Platypus already knows (steps, store).
- **Honest UI:**
  - every judgement says it comes from patterns ("probable");
  - the options and the Book say clearly: "**Platypus is not a protection.** It recognises known patterns and can miss what it does not know."
- **Privacy:**
  - the store keeps the rule id, the level, the prudence reasons and the target made relative to the project, never the full command;
  - where a "shape" of the command helps, use it with the arguments replaced (`git reset --hard <ref>`);
  - declare the new fields in the store's privacy guard (2.13 S6).
- **Fail open:**
  - every hook answer within the 2.11 budget;
  - on timeout, error or Platypus closed, Claude Code goes on as if Platypus did not exist;
  - the classifier must answer in under 20 ms at p99.
- **Never:**
  - `deny`, and never rewriting a command;
  - the guard switched on by default, or switched on from anything other than the local office or the options;
  - in the future 3.0 server mode the guard stays disabled, like approvals from the office.
- **Isolation:** `PLATYPUS_PORT=47880`, `PLATYPUS_DATA_DIR=<worktree>/.platypus-dev`.
- **Texts:**
  - `tr()`/`trn()`;
  - English translations in `src/i18n/locales/en/fear.json`;
  - messages to the agent in the language decided in 2.11.
- **Also never:**
  - `git push`, merge into main, or rewriting commits;
  - `npm run hooks:install` without Max's permission given at that moment;
  - Max's real data in the repository;
  - the @decisyon.com address as commit author.

## R1 · Risk classifier  [x]

- **Files:** `src/core/risk.js` and a data table of rules in `src/core/risk-rules.js`.
- **Input:** the tool name, the tool input, cwd and project root.
- **Output:** `{level 0–3, ruleIds, category, reasons, reach, undo}`, where `undo` says how one would go back, if one can.
- **Shell parsing**, without running anything:
  - split on `&&`, `||`, `;`, `|` and newlines;
  - enter `bash -c "…"`, `sh -c`, `xargs`, `sudo`, `env VAR=…`, `time`, `nohup`;
  - ignore what is only a string (`echo "rm -rf /"`, `grep "DROP TABLE"`, comments, heredoc bodies passed to `cat`).
  - PowerShell: `Remove-Item -Recurse -Force`, `Set-Content` outside the project, `git` the same.
  - cmd: `rd /s /q`, `del /f /s /q`.
- **Levels and categories** (each rule has an id, a level, a text, the prudence that counts for it and how to undo):
  - **1 · attention:**
    - more than 20 files modified in one turn (from the steps);
    - lockfiles rewritten;
    - dependencies added;
    - CI or config changed;
    - `.env` touched.
  - **2 · danger:**
    - `git reset --hard`, `git checkout -- .` / `git restore .`, `git clean -fd`, `git stash drop/clear`, `git rebase`, `git branch -D`;
    - `rm -r` of files not tracked by git;
    - `sudo`, `chmod -R`, `chown -R`;
    - writing over untracked files.
  - **3 · irreversible:**
    - `git push --force` / `-f` / `--force-with-lease` on a shared branch, or any push to `main`/`master`;
    - `rm -rf` outside the project or on home or root;
    - SQL `DROP`/`TRUNCATE`, or `DELETE`/`UPDATE` without `WHERE`;
    - `terraform apply/destroy`, `kubectl delete`, `helm uninstall`, `docker system prune -a`, `docker volume rm`;
    - deploy and publish commands (`npm publish`, `gh release create`, `vercel --prod`, …);
    - writes outside the working directory;
    - MCP tools whose name means an external effect (`send`, `post`, `delete`, `pay`, `transfer`, `publish`, `share`);
    - reading `~/.ssh`, `~/.aws` or `.env`, then a network call in the same turn.
- **Not risky** (to avoid crying wolf):
  - `rm -rf node_modules`, `dist` or `build`, and caches, which come back with a command;
  - `git push` to a feature branch;
  - `DELETE … WHERE id = …`;
  - `terraform plan`.
- **Tests:** a table in `scripts/unit-test.js` with at least 150 commands and their expected level, including tricky quoting, Windows variants and the false positives above.
- **Benchmark:** p99 under 20 ms.

## R2 · Prudence  [x]

- **File:** `src/core/prudence.js`.
- **Input:** the risky action and the recent steps of that agent (and of the session).
- **Output:** `{score 0–1, present: [...], missing: [...]}`.
- **Prudence that counts:**
  - looked first: `git status`, `git diff`, `ls` or Read of the target, `terraform plan` before `apply`, a `SELECT` with the same `WHERE` before a `DELETE`;
  - a safety copy: commit, stash or branch in the last N actions, or a copy of the target;
  - dry-run flags (`--dry-run`, `-n`, `--what-if`);
  - a clean working tree (from the output of `git status`, if 2.9 already reads tool results);
  - **the user asked for it:** the verb and the target appear in the user's last prompt. This is lexical, so it is marked "probable".
- **Tests:** sequences of steps with and without each kind of prudence.

## R4 · Scars  [ ]

- **What to watch:** after a level ≥ 2 event, the next N actions of the agent and the next prompt of the user.
- **Signs of damage:**
  - new errors on files the action touched;
  - files that existed and are now ghosts (2.9);
  - recovery attempts (`git reflog`, `git fsck --lost-found`, restore from a backup);
  - the user writing "you deleted", "undo", "hai cancellato", "ripristina" (lexical, "probable").
- **When the signs are there:**
  - the event gets `outcome: damage`, with the evidence as references to steps;
  - the Book gets a lesson of kind `scar`: "here `<shape>` destroyed work on `<relative target>`; next time: `<missing prudence>`".
  - The scar has its weight and its half-life like the other lessons, but it decays slower (half-life 90 days).
- **The Nonno** tells scars first, in the same project.

## R5 · The office  [ ]

- **Risky action with prudence:** the character sweats and trembles for a few seconds. The fear is right.

### 2026-11-19 · R1 · Risk classifier

- **Files:** `src/core/risk.js` (the classifier), `src/core/risk-rules.js` (the rules as data: 46 rules with level, category, reach, shape, text, undo and the kinds of prudence that count), `src/i18n/locales/en/fear.json`, `scripts/risk-cases.js` (the table), tests in `scripts/unit-test.js`.
- **How it works:** `classify({ tool, input, cwd, root, … })` returns `{ level, ruleIds, category, reasons, reach, undo, prudence, shape, targets, marks }`. A small lexer splits a bash, PowerShell or cmd line into commands and words without expanding anything; a scanner walks the commands, enters `sudo`, `env`, `xargs`, `time`, `nohup`, `npx`, `bash -c`, `cmd /c`, `powershell -Command`, `eval`, `ssh host …`, `find -exec`, `$(…)` and backticks, follows `cd` and `git -C`, and reads heredoc bodies only where a shell or a SQL client executes them. It never runs, opens or calls anything.
- **Privacy, already here:** the result carries the rule's fixed `shape` (`git reset --hard <ref>`), never the arguments; `targets` holds only paths inside the project, relative to it. A path outside the project is never reported. Tests check both.
- **What the caller may add, all optional:** `branch` (the current branch), `fileState(abs, rel)` (tracked, untracked, missing), `turnFilesModified`, `turnReadSecrets`. The result's `marks` (`readsSecret`, `network`) let the caller keep the last two up to date. R3 will wire them.
- **Verified:** the table has 346 commands (126 at level 0, 20 at 1, 62 at 2, 138 at 3), with tricky quoting, Windows variants and the plan's false positives; p99 is 0.06 ms (limit 20), and a 200,000-character command answers in about 6 ms. `npm test` → 1199 ok, "Tutto a posto."; `npm run i18n:check` → 0 missing. The store conformance suite runs inside `npm test`.
- **Decisions:**
  - The table lives in its own file, `scripts/risk-cases.js`, read by `scripts/unit-test.js`: 346 rows inside `unit-test.js` would bury the other tests.
  - **Force push has three answers**, where the plan had one: a shared branch (main, master, develop, staging, release/…) or `--all`/`--mirror` is level 3; a named working branch is level 1 (rewriting one's own branch after a rebase is everyday work); an unknown branch is level 2.
  - **`rm -r` inside the project** is level 2 unless the target comes back with a command (node_modules, dist, build, caches…) or the caller says git tracks it. Without `fileState` the classifier cannot know, and says "a folder git may not know".
  - **Discarding one file** (`git checkout -- file`, `git restore file`) is level 1; several files, a folder or `.` is level 2.
  - **Writes outside the project** are level 3 as the plan says, except temporary folders and `/dev/null`.
  - `ssh host "cmd"`: the command is classified as if nothing were inside the project.
  - Added beyond the plan's list, same spirit: `find -delete`, `curl … | sh`, `dd of=/dev/…`, `mkfs`, database resets (`rails db:drop`, `prisma migrate reset`, `manage.py flush`, `redis-cli FLUSHALL`), cloud deletes (`aws s3 rm --recursive`, `gcloud … delete`), `docker push`, `rsync --delete`.
- **Known limits** (for the "not a protection" sentence):
  - a command hidden in a variable (`RM=rm; $RM -rf /`), in a script file (`bash clean.sh`, `psql -f drop.sql`, `npm run deploy`, `make deploy`) or in a language one-liner (`python -c`, `node -e`) is not seen;
  - only the first 20,000 characters of a command are read;
  - "the user asked for it" and the state of git are not the classifier's job: they come in R2 and R3.
- **Doubt for Max:** is level 1 right for a force push to a working branch, or do you want it at level 2 like the plan's list?

### 2026-11-19 · R2 · Prudence

- **Files:** `src/core/prudence.js`; one line in `src/core/worldmap.js`; tests in `scripts/unit-test.js` (51 checks).
- **What it does:** `assess({ risk, action, steps, prompt })` returns `{ score, present, missing, probable }`. It looks at the agent's last 12 actions that did not fail, and only at the kinds of prudence the rule declares (for `sudo`, only "the user asked").
  - **looked:** by category. For git: `git status`, `diff`, `log`, `stash list`. For files: `ls` or a read of the target itself (looking at another folder does not count). For SQL: a `SELECT` on the same table. For infrastructure: `terraform plan`, `kubectl get`, `helm list`.
  - **backup:** a commit (not `--amend`), `git stash`, a new branch or tag, a copy of the target, a database dump. A commit does not count as a backup of a database.
  - **dryrun:** the same tool run with `--dry-run`, `-n`, `--what-if`, or `terraform plan`, `git clean -n`.
  - **clean:** the last `git status` said the tree was clean and no edit came after it.
  - **asked:** the last user message contains the command itself, or a verb for that kind of action plus a word of the target (branch, table, folder). It is lexical, so it is returned in `probable` too.
- **Score:** each kind present adds its weight, up to 1: looked 0.3, backup 0.6, dryrun 0.6, asked 0.6, clean 0.7. `missedFear(risk, prudence)` is true for level 2 or more with a score under 0.5. So looking alone is not enough; any one of the others is.
- **The clean tree:** 2.9 read tool results but kept none of the text. `worldmap.js` now sets `clean: true/false` on a `git status` step from its output (`gitStatusClean`), and keeps nothing else. A test checks the output text is not in the step.
- **Privacy:** the prompt is read inside `assess` and nothing of it is returned. A test checks it.
- **Verified:** `npm test` → 1250 ok, "Tutto a posto."; `npm run i18n:check` → 0 missing (this task adds no text).
- **Decisions:**
  - The weights and the 0.5 threshold are mine: the plan gave the list of kinds and the threshold, not the weights. They are constants at the top of the file.
  - For an MCP tool the verb alone is enough for "asked": the user writes "send the mail", not the tool's technical name.
  - The window is 12 actions, not a time: an agent that waits ten minutes has not become less prudent.
- **Doubts for Max:**
  - Is "looked alone is not enough" right? With it, `git status` then `git reset --hard` on a dirty tree is still a missed fear.
  - The R1 entry said 45 rules; they are 46 (corrected above).
