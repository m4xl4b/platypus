# 2.11 · Check on a real Claude Code session

Run by Max, not by the loop: the test session uses his account. It takes about five minutes and answers what the documentation leaves open. Nothing in 2.11 waits for it, but its results decide whether the `PreToolUse` variants (B2, B4) are built.

## What it does and what it touches

`node scripts/feedback-check.js` creates a throwaway folder in the system's temporary directory (`platypus-feedback-check`) with:

- `project/`: a tiny project whose `npm test` fails on purpose, and the hooks in **its own** `.claude/settings.json`. Your `~/.claude/settings.json` is not touched, and the hooks exist only for sessions opened in that folder.
- `data/`: the settings and book of a test Platypus, started on port 47811 with no access to your sessions.

The test Platypus answers every hook with a fixed marker: `PLATY-START` (SessionStart), `PLATY-PRE` (PreToolUse), `PLATY-POST` (PostToolUse), `PLATY-FAIL` (PostToolUseFailure) and, once, a Stop block asking for `PLATY-STOP`. The markers the model can repeat back are the ones that reach it.

Your normal Platypus can stay open: the check uses another port.

## Steps

1. In the repository, on the `sviluppo-2.11` branch:
   ```
   node scripts/feedback-check.js
   ```
   It prints the folder to open and the prompt to send.
2. Open a second terminal in the folder it printed and start Claude Code there (or open that folder in the Claude desktop app). If it asks to trust the folder and its hooks, say yes.
3. Send the prompt printed by the script. Claude runs `npm test` (fails), reads `notes.txt`, tries to read `missing.txt`, then lists the "Platypus check" lines it received.
4. In the first terminal, each hook that arrived is a `[feedback-check]` line: event, tool, agent, and whether the request carried an `Origin` header.
5. Press Ctrl+C in the first terminal, then send one more prompt in the same Claude session, for example "read notes.txt again". Claude Code must behave as usual, with at most a hook error notice.
6. Optional, if the hooks never arrived in step 4: repeat from step 1 with `node scripts/feedback-check.js --curl`, which installs the same hooks as `curl` commands instead of `http` hooks.
7. Delete the `platypus-feedback-check` folder.

## Results (Windows, 2026-11-18)

Run by the Windows tests loop with Max's permission, on Windows 11 and Claude Code 2.1.11, with `claude -p` (non-interactive), the hooks in the project's own settings, and the check on port 47850. Details in the Journal (Windows) of `docs/plans/platform-tests.md`.

| Question | Result |
|---|---|
| Claude Code version | 2.1.11 |
| Do `http` hooks reach Platypus? | Yes (no need for `--curl`) |
| Which markers did the model see? | `PLATY-PRE`, `PLATY-POST`, `PLATY-FAIL`; not `PLATY-START` |
| Does `PreToolUse` context reach the model? | Yes (`hook_additional_context` in the transcript) |
| Which event fires for the failing `npm test`? | `PostToolUseFailure` |
